# 上鱼角色动画：目标设计与验收标准

> 状态：**设计已明确，代码尚未实施。**
>
> 当前 `LandingView` 只是静态立绘的位移、缩放、旋转与淡入淡出，只能作为状态链路占位，不能按本文标准验收为“角色动画”。

## 1. 目标

体力磨空后，玩家看到的不是“钓上一张 meme 图”，而是这个角色从水中发力、破水、腾空并扑到眼前的短演出。

角色自身的动作是主体；整体轨迹、缩放、水花和镜头反馈只负责加强空间关系。

这套演出还要满足：

- 小、中、大肥鱼可以拥有不同动作和节奏。
- 后续可以接入其他角色，也可以接入非鱼类对象。
- 新增对象主要通过配置和资源扩展，不在 UI 中不断增加 id 判断。
- 动画异常不会把一局永久卡在 `LANDING`。

---

## 2. 什么算完成，什么不算

### 不算角色动画

以下做法即使组合使用，也仍只是静态图运动：

- 同一张图从水面移动到屏幕中央。
- 同一张图放大、缩小、旋转、抖动或回弹。
- 给同一张图加阴影、相框、速度线、水花和台词。
- 把 JPG 换成透明 PNG，但角色从头到尾仍保持同一姿态。
- 用很夸张的鱼线或镜头晃动遮住角色没有动作的事实。

这些手段可以保留为演出辅助，但不能作为任务完成的核心证据。

### 最低完成标准

角色在播放过程中必须出现可辨识的自身姿态变化，并至少表达四类动作信息：

| 拍点 | 角色动作 | 场景配合 |
|---|---|---|
| 蓄力 | 身体下压、收紧、后仰或对应对象的准备姿态 | 浮标下沉、水面预兆 |
| 破水 | 身体展开、甩动或冲出姿态，明显区别于蓄力帧 | 水花从浮标位置出现 |
| 腾空扑近 | 朝向玩家的动作姿态，肢体或轮廓继续变化 | 根节点沿轨迹接近镜头 |
| 到达前景 | 有明确的扑到、压近或撞击姿态，不停在通用站立图 | 冲击反馈、台词进入 |

“四类动作信息”不要求机械地只画四张图。正式素材可以拆成更多过渡帧，但不能用四张相同轮廓的文件凑数。

## 3. 推荐实现路线：角色序列帧 + 独立空间编排

当前素材以单张角色图为主，第一阶段推荐使用**透明背景序列帧**。它最直接地保证角色轮廓和姿态真的变化，也不要求先建立复杂骨骼系统。

等效的角色部件动画也可接受，但必须能表现同样的姿态变化。只把一个完整角色当成一个刚性部件，仍不合格。

### 两类运动必须分开

```text
角色局部动画：蓄力 → 破水 → 腾空 → 扑到
                  由角色自己的帧或部件驱动

角色根节点运动：浮标位置 → 出水位置 → 镜头前景
                  由 LandingView 的轨迹、缩放和透视编排驱动
```

同一根 Tween 可以同时做轨迹和缩放，但它不能替代左边的角色局部动画。

### 为什么先做序列帧

- 美术验收直观：每张图就能看出姿态是否不同。
- 新角色接入简单：提供自己的帧目录和配置即可。
- 非鱼类对象不受鱼骨、尾巴等结构假设限制。
- 不需要把搏斗规则或场景状态引入动画资源。

代价是素材数量和导出工作增加。若后续片段很多，再评估部件化或骨骼化，不在第一阶段提前堆系统。

## 4. 建议资源结构（尚未创建）

以下命名是下一阶段实施提案，不是当前项目已有文件：

```text
assets/
└── landing/
    ├── small_fish/
    │   ├── pose_00.png        蓄力
    │   ├── pose_01.png        发力
    │   ├── pose_02.png        破水
    │   ├── pose_03.png        腾空
    │   ├── pose_04.png        扑近
    │   └── pose_05.png        到达前景
    ├── mid_fish/
    │   └── ...
    └── big_fish/
        └── ...
```

资源要求：

- 使用带 alpha 的 PNG 或等效透明资源，不能带 JPG 的矩形底色。
- 同一角色的序列帧使用一致画布尺寸和统一锚点，避免播放时无故跳动。
- 文件名只用 ASCII，顺序由配置显式给出，不依赖不透明的文件排序。
- 原始绘制文件放 `素材/` 或不参与导出的源目录，游戏只导入发布用资源。
- 每个角色至少准备能区分蓄力、破水、腾空、到达前景的独立姿态。

## 5. 建议配置接口（尚未接入代码）

### 5.1 目标只绑定动画标识

在 `data/fish.json` 中增加可选字段：

```json
{
  "id": "big",
  "name": "大肥鱼",
  "landing_id": "big_fish_pounce"
}
```

`landing_id` 是表现绑定，不参与落点、搏斗、收集或结局规则。未提供时可以回退到 `id`，但最终回退策略要在实现时统一，不要每个视图各写一套。

不同档次的肥鱼使用不同 `landing_id`。即使它们暂时复用部分帧，也应通过配置共享，而不是复制分支代码。

### 5.2 动画清单独立保存

建议增加 `data/landings.json`：

```json
{
  "clips": {
    "big_fish_pounce": {
      "frames": [
        "res://assets/landing/big_fish/pose_00.png",
        "res://assets/landing/big_fish/pose_01.png",
        "res://assets/landing/big_fish/pose_02.png",
        "res://assets/landing/big_fish/pose_03.png",
        "res://assets/landing/big_fish/pose_04.png",
        "res://assets/landing/big_fish/pose_05.png"
      ],
      "fps": 10.0,
      "breach_frame": 2,
      "impact_frame": 5,
      "scale": 1.0,
      "anchor": [0.5, 0.75]
    }
  }
}
```

建议字段语义：

| 字段 | 必需 | 含义 |
|---|---|---|
| `frames` | 是 | 有序角色姿态资源，不循环 |
| `fps` | 是 | 角色局部动画播放速度 |
| `breach_frame` | 是 | 破水关键帧，用于同步水花和根节点出水 |
| `impact_frame` | 是 | 到达前景关键帧，用于同步冲击和台词 |
| `scale` | 否 | 角色素材的独立尺寸修正，默认 1 |
| `anchor` | 否 | 角色统一锚点，便于对齐不同素材 |

字段名和文件结构可以在实现前一次冻结，但冻结后必须由统一加载器解析，并提供默认值、路径校验和警告。`FishSpec` 不应膨胀成一整份动画播放器配置。

## 6. 建议组件边界（尚未实现）

以下是职责名，不要求机械照搬类名：

| 组件 | 职责 |
|---|---|
| `LandingView`（保留对外入口） | 接收目标和浮标位置，编排轨迹、场景效果、台词，发出一次 `finished` |
| 动画配置加载器 | 读取 `landing_id` 对应清单，验证资源和关键帧 |
| 角色播放器 | 按 fps 切换角色姿态，报告破水和冲击拍点 |
| 轨迹与效果层 | 根节点位移、透视缩放、水花、必要的轻微镜头反馈 |

`game_root` 继续只负责：

```text
landing_started(fish)
  → LandingView.play(fish, lake.bobber_screen_pos())
  → LandingView.finished
  → FishingSession.landing_done()
```

`FishingSession` 不需要知道 fps、帧路径、角色锚点或水花参数。

### 禁止的结构

```gdscript
# 不接受：每加一个角色就让视图继续膨胀
if fish.id == "small":
    ...
elif fish.id == "mid":
    ...
elif fish.id == "big":
    ...
elif fish.id == "new_character":
    ...
```

差异进入配置与资源，通用播放流程只保留一份。

## 7. 时间与节奏

不要给所有角色强制同一套秒数。建议按拍点同步，而不是写死“第 0.55 秒一定破水”。

```text
开始
  │  蓄力帧
  ├─ breach_frame：破水、出水轨迹开始、水花触发
  │  腾空与扑近帧
  ├─ impact_frame：到达前景、冲击反馈、台词进入
  │  短暂停留
  └─ 淡出并完成，发出 finished
```

推荐节奏意图，而非当前数值：

- 小肥鱼：准备短、动作快、落点轻，突出灵活。
- 中肥鱼：破水和腾空更完整，节奏均衡。
- 大肥鱼：蓄力更明显、扑近更有重量，冲击更强，但不能靠单纯放大图片表现重量。
- 非鱼类对象：按自身形态定义拍点，不强行套“摆尾”。

`landing_timeout` 应略长于最长正常片段。正常完成由播放器回报，超时只负责异常兜底。

## 8. 降级与错误处理

正式系统仍要允许项目缺素材时启动，但降级不能伪装成达标：

| 问题 | 建议行为 |
|---|---|
| `landing_id` 没有配置 | 警告，使用明确的通用占位演出或快速收尾 |
| 某帧路径不存在 | 报告具体路径；跳过无效片段或使用完整有效片段，不播放半坏动画 |
| `frames` 为空 | 警告并快速收尾，不卡状态机 |
| 关键帧索引越界 | 钳制或回退到安全拍点，同时警告 |
| 正常完成信号未发出 | `landing_timeout` 推进，并保留可诊断日志 |
| 连续触发播放 | 停止旧片段和旧 Tween，确保最终只完成一次 |

开发阶段可以继续显示静态占位，方便排查；版本验收时，占位回退必须列为未完成，而不是默认视为通过。

## 9. 测试方案

### 自动配置检查

为动画清单增加无窗口测试：

- 每个被目标引用的 `landing_id` 都存在。
- `frames` 非空，所有路径可加载。
- `fps > 0`。
- `breach_frame` 和 `impact_frame` 在合法范围内。
- 同一角色配置不能只用一张帧冒充完整动画。
- 重播和异常收尾不会重复推进一局。

自动测试能证明资源完整，不能证明美术动作好看或姿态差异足够明显。

### 连续播放检查

现有 `04_landing.png` 只证明某一帧构图。正式验收至少保存关键拍点截图，或提供一段连续录屏：

```text
landing_00_charge.png
landing_01_breach.png
landing_02_airborne.png
landing_03_impact.png
```

这些截图应来自同一次连续播放，而不是分别摆拍四张静态图。

### 扩展性检查

新增一个测试对象，只添加目标配置、`landing_id`、动画清单和资源：

- 不改 `FishingSession`。
- 不改角色播放器的 id 分支。
- 能播自己的片段。
- 能正常完成并回到 `AIMING` 或进入 `ENDED`。

## 10. 最终验收清单

### 角色动作

- [ ] 角色自身有多个清晰可辨的姿态，不只是纹理变换。
- [ ] 蓄力、破水、腾空扑近、到达前景四类信息都能看清。
- [ ] 角色动作与从浮标到前景的空间轨迹同步。
- [ ] 没有 JPG 矩形边界、突兀跳锚或明显素材抖动。

### 角色差异

- [ ] 小、中、大肥鱼不是仅改尺寸或 `tint` 的同一段占位。
- [ ] 至少大肥鱼拥有符合其设定的独立扑近动作。
- [ ] 新角色或非鱼类对象可以通过同一协议注册。

### 工程行为

- [ ] 搏斗规则没有因为动画系统而依赖 UI。
- [ ] 破水、冲击和台词由明确拍点触发。
- [ ] 正常播放只发出一次完成信号。
- [ ] 缺资源有警告和降级，`LANDING` 不会永久卡死。
- [ ] `landing_timeout` 不截断最长正常演出。
- [ ] 新增角色不需要在 `LandingView` 添加 id 分支。

### 证据

- [ ] 自动资源检查通过。
- [ ] 关键拍点连续截图或录屏已查看。
- [ ] 完整输入链路和既有逻辑自测仍通过。

## 11. 建议实施顺序

本阶段只定文档，不执行以下步骤。恢复编码后按此顺序推进：

1. 同步遗留的结算统计和输入探针，先让当前版本验收口径一致。
2. 冻结动画清单字段和资源目录约定。
3. 为一只角色制作最小可用的透明姿态序列，优先大肥鱼。
4. 实现通用播放器与 `LandingView` 编排，保留现有 `landing_done()` 协议。
5. 用大肥鱼完成连续动作验收，再接入小、中肥鱼。
6. 添加一个非默认角色验证配置扩展，最后统一重拍文档截图。

不要把“先让三条鱼都能播同一张静态图”列为本任务完成；那仍是当前占位状态。
